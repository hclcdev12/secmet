SecMet — Outil embarqué (TestDisk)
==================================

Les paquets .deb, .rpm et l'AppImage SecMet incluent une copie du binaire
testdisk sous /usr/lib/secmet/bin/, utilisée en priorité par secmet-helper
(le testdisk du système sert de repli). Elle est copiée sans modification
depuis la distribution de construction, si testdisk y est installé. Les
accès disque eux-mêmes (IDENTIFY, SMART, SANITIZE, SECURITY ERASE, NVMe
Format/Sanitize, lecture et écriture) sont réalisés nativement par
secmet-helper (SG_IO, ioctl NVMe, sysfs) : nvme-cli, hdparm et
smartmontools ne sont plus embarqués ni requis.

Fichiers concernés
------------------

  /usr/lib/secmet/bin/testdisk   (si présent)
  /usr/lib/secmet/lib/*.so.*     (bibliothèques que testdisk lie sur la
                                  machine de construction, hors glibc)

Sources
-------

État actuel : SecMet renvoie aux archives des distributions dont les
binaires sont issus.

  TestDisk (amont)  : https://www.cgsecurity.org/wiki/TestDisk
  Ubuntu            : apt source testdisk ncurses util-linux e2fsprogs ntfs-3g
                      https://launchpad.net/ubuntu/+source/testdisk
  Fedora            : dnf download --source testdisk (et les paquets des
                      bibliothèques) ; https://src.fedoraproject.org/rpms/testdisk

Ce renvoi correspond à l'option de la GPL-2.0 §3(c), réservée à une
distribution non commerciale ; les archives ne conservent pas toujours la
version exacte d'un binaire ancien. Pour une distribution commerciale,
l'éditeur doit fournir lui-même les sources correspondantes des versions
embarquées : soit jointes à la release (archive de sources par version),
soit par une offre écrite valable au moins 3 ans (GPL-2.0 §3(b)). Ce n'est
pas encore fait en 0.4.0 (voir THIRD_PARTY_LICENSES.md, section 8).

Relation avec SecMet
--------------------

SecMet (licence GPL-3.0-or-later) reste un programme distinct. testdisk est
un programme tiers exécuté par secmet-helper en processus séparé, dont la
sortie texte est analysée ; selon l'interprétation courante (FAQ GNU,
« mere aggregation »), son inclusion dans le paquet .deb / .rpm /
l'AppImage constitue une redistribution d'un logiciel tiers à côté de
SecMet, pas une œuvre dérivée du code source SecMet.
